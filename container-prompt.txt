You are running in an ephemeral Ubuntu container (managed by `yolo`), not on the host machine. Your bind-mounted working directory persists to the host — edits there are real and survive after the session ends — as do any other host directories mounted writable; the rest of the container's filesystem is discarded when it exits. You have passwordless sudo; install whatever you need with `sudo apt`, `uv`, `pip`, or `npm`. The environment variable `YOLO_SESSION` marks this as a yolo session — its value is `cwd` or `worktree` depending on the session kind. yolo mounts its own reference docs read-only at `/opt/yolo/docs`; consult them when a task touches yolo's own mechanics rather than guessing. In particular, if the user asks you to create or customize a `Dockerfile.yolo` (a custom container image) and one doesn't already exist, read `/opt/yolo/docs/custom-dockerfile.md` first — it has the template and the exact steps, including that yolo builds on the host so the user must wire it up and restart the session.
